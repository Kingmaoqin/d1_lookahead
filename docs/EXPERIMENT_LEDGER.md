# 第 0 章 · 词表：读下文之前先看这里

## 0.1 这个项目在研究什么

**扩散语言模型（DLM，Diffusion Language Model）**：和 ChatGPT 那种"从左到右一个
词一个词往下写"的模型不同，它从"整句话全是空格"开始，反复迭代，每一轮揭开若干
个位置，直到填满整句。

**掩码扩散（masked diffusion）**：上面那种模型的一种具体做法——"空格"就是一个
特殊符号 `[MASK]`（掩码），去噪过程就是把 `[MASK]` 换成真词。

**揭示顺序（unmasking order）**：先揭开哪个位置、后揭开哪个位置。这是扩散语言
模型独有的自由度，**也是本项目的研究对象**。

**本项目要回答的那一句话**：
> 有些方法（POKE、LookUM）在生成时花额外算力"向前模拟一下"，看看哪个位置先揭开
> 更好。**能不能不模拟，直接从模型自己的内部状态里读出这个答案？**

如果能，就省掉了那份额外算力。如果不能，那些方法的额外算力是必要的。

## 0.2 强化学习记号（判断"哪个选择更好"的标准语言）

| 记号 | 全称 | 大白话 |
|---|---|---|
| **状态 s** | state | 当前这句话填到一半的样子（哪些位置填了、填了什么） |
| **动作 a** | action | 这一步选择揭开哪个位置、填什么词 |
| **V(s)** | 状态价值 value | 在状态 s 下**照常往下走**，最后能有多好 |
| **Q(s,a)** | 动作价值 | 先做动作 a、**再照常往下走**，最后能有多好 |
| **A = Q − V** | **优势 advantage** | 这个动作**比照常走好多少**。这是调度器真正需要的量 |

**核心区别（全项目结论都绕着它转）**：
- **V 是"水平量"（level）**——这个局面整体好不好
- **A 是"差分量"（differential）**——同一个局面里，这几个选择哪个更好

## 0.3 参考策略与推演

**π_ref（读作 pi-ref，参考策略）**：一个固定下来、可复现的解码器。所有"价值"
都是**相对它**定义的——换一个 π_ref，同一个动作的优势值就变了。

本项目用过三种 π_ref：

| 名称 | 做法 | 备注 |
|---|---|---|
| **祖先采样** ancestral sampling | 揭示顺序是**均匀随机**排列 | 掩码扩散模型"原本设计的"采样方式 |
| **置信度解码** confidence decoding | 每步挑模型**最有把握**的位置先揭开 | MaskGIT/LLaDA 的主流做法，**也是 POKE/LookUM 实际用的** |
| **block diffusion** 分块扩散 | 按块推进，块内按置信度阈值提交 | 第三个骨干（Nemotron）用的 |

**推演（rollout）**：从某个中间状态出发，让 π_ref 一路解码到底，看最终得到什么。
本项目用它**实测**未来价值，而不是估计。

**K**：每个状态跑多少条推演。K 越大，测出来的价值越准（噪声按 1/K 下降）。

**视界 H（horizon）**：做完这个动作之后，**往后数多少次提交**来计分。H=16 就是
只看接下来 16 次提交的结果。

## 0.4 四种"优势"目标（本项目测过的四个不同的 A）

| 代号 | 全称 | 到底是什么 | 难度 |
|---|---|---|---|
| **A_full** | Path-LL 完整优势 | 包含**动作自己那个词的对数概率** | 较易 |
| **A_pertok** | A_full 的逐词平均 | 上面这个除以词数。**这是预注册的主目标** | 较易 |
| **A_future** | 下游优势 | **只看动作对后续的影响**，剔除动作自己那个词 | **更难**——因为动作自己的对数概率本来就是一个免费的控制特征 |
| **A_task** | 任务优势 | 做了这次提交之后，**最终答案对不对**的概率变化 | 最难，但**最有意义** |

**Path-LL（路径对数似然，Path Log-Likelihood）**：把一条解码轨迹上每次提交的词
的对数概率加起来，衡量"这条路走得好不好"。**这是 POKE 论文提出的代理指标**，
不是真实任务效果。

> ⚠️ **一条关键发现**：`corr(A_PathLL, A_task) ≈ +0.037`——Path-LL 优势和真实
> 任务优势**几乎不相关**。所以所有基于 Path-LL 的结论**不能外推到真实任务**。

## 0.5 探针与它要打败的对手

**探针（probe）**：在**冻结的**（不再训练的）模型内部状态上训练的一个小预测器。
用"能不能预测某个量"来判断该量是否被编码在表征里。

**线性探针（linear probe）**：探针只允许是线性函数（就是加权求和）。**必须用
线性**——如果只有复杂非线性能读出来，就不能说这个量被"表示"了。

**探针能看到的三种输入**：

| 代号 | 全称 | 是什么 | 关键性质 |
|---|---|---|---|
| **cheap** | 廉价控制特征 | 不用看模型内部就能拿到的东西：置信度、熵、margin、对数概率投影等 | **探针必须打败它**，否则说明隐藏状态没提供新信息 |
| **h_local** / `h_i` | 候选位置的隐藏向量 | 模型在**这个候选位置**上的内部向量 | **在一个状态内每个候选各不相同**→ 只有它能排序候选 |
| **h_global** / `h_g` | 全句池化的隐藏向量 | 模型对整句话的内部向量取平均 | **在一个状态内是常数**→ **它按定义无法排序候选** |

> 这个区分是全项目的枢纽：**h_global 能读出 V（水平量），h_local 才可能读出
> A（差分量）。** 如果只有 h_global 有效，那说明模型只知道"局面好不好"，不知道
> "哪个选择更好"。

**探针代号**（来自 `scripts/rescue_broad_screen.py`）：

| 代号 | 含义 |
|---|---|
| `P0_cheap` | 只用廉价控制特征（基线） |
| `P0_hi` | 只用候选位置隐藏向量 |
| `P0_hg` | 只用全句池化隐藏向量 |
| `P0_cheap_hi` | 廉价 + 候选位置 |
| `P0_cheap+H` | 廉价 + 候选位置 + 全句 |
| `P2_bilinear_r4` | **秩 4 双线性探针**：让候选向量和全句向量**相乘**产生交互项，看"同一个候选在不同局面下价值不同"这种关系能不能被捕捉 |
| `no_state_interaction` | 双线性的对照版：**去掉交互项**，只保留加法。用来问"交互项本身有没有用" |
| `CONTROL:shuffle_hg` | **打乱**全句向量（张冠李戴）——如果它和真的一样好，说明真信号不存在 |
| `CONTROL:gauss_hg` | 把全句向量换成**纯随机高斯噪声**——同上，属于证伪控制 |

## 0.6 评价指标

| 指标 | 大白话 | 好的方向 |
|---|---|---|
| **R²** 决定系数 | 预测解释了多少比例的变化。0 = 和"永远猜平均值"一样，**负数 = 比猜平均值还差** | 越大越好 |
| **ΔR²**（增量） | 加入隐藏状态后，R² 比只用廉价特征**高出多少**。**本项目主统计量** | > 0 |
| **within-R²**（同状态内 R²） | 先把每个状态内部的均值从标签和预测里**都减掉**再算 R²。它剥离了"这个局面好不好"，**只剩"同一局面里哪个候选更好"** | > 0 |
| **concordance**（一致率） | 同一状态内任取两个候选，探针判断"谁更好"**判对的比例**。**随机猜 = 0.5**。这是调度器真正面对的决策 | > 0.5 |
| **AUC** | 排序质量。0.5 = 随机，1.0 = 完美 | 越大越好 |
| **Spearman ρ** | 秩相关，衡量排序一致性 | 越大越好 |

**噪声天花板（noise ceiling）**：因为标签本身是用 K 条推演**测**出来的，自带
测量误差，所以**任何**预测器的 R² 都不可能超过某个上限。

> ⚠️ **报 R² 而不报天花板，数字没有意义。** 举例：R²=0.48 看着不高，但如果天花板
> 是 0.99，那就是拿到了可达信号的 48%；如果天花板只有 0.5，那就是几乎拿满了。

**SNR（信噪比）**：标签里"真信号方差"与"测量噪声方差"之比。**低于 1 意味着噪声
比信号大**，此时的零结果**没有信息量**（不能说"没有信号"，只能说"没测出来"）。

**聚类 bootstrap（聚类自助法）**：估计不确定性时，重抽样以**整篇文档为单位**整块
抽取，而不是逐条抽。因为同一文档里的样本互相依赖，逐条抽会**低估**不确定性。
产出**95% 置信区间**——如果区间不包含 0，就说这个效应"显著"。

## 0.7 「seed（种子）」在本项目有三种，绝对不能混

| 名称 | 含义 | 衡量什么 | 陷阱 |
|---|---|---|---|
| **划分种子** split_seed（0/1/2） | 把**同一批数据**按文档重新切成 训练/验证/测试 | **划分敏感性** | ⚠️ **不是独立重复实验**。三个划分共用同一批标签，高度相关，**不能当三次独立复现来算显著性** |
| **推演种子** CRN seed（就是 K） | 每个状态跑 K 条推演 | **标签测量噪声** | 噪声天花板就是它算出来的 |
| **训练种子** init seed | 非凸探针（双线性、MLP）的**权重初始化** | **优化不稳定性** | ⚠️ Task C 上换一组初始化，结论从 +0.027 变 +0.015，控制组还反超 |

**CRN（共同随机数，Common Random Numbers）**：让两条要对比的推演使用**完全相同
的随机数**，这样它们的差值只反映"动作不同"，不掺杂随机波动。方差缩减标准手段。

**Rao-Blackwell 化**：把"抽样得到的随机量"换成它的**条件期望**。期望不变（全期望
公式保证），方差严格更小。本项目实测缩减 4.1–9.9 倍（中位 6.2 倍）。

## 0.8 预注册门禁（开工前就写死的判定标准）

**预注册（pre-registration）**：在**看到结果之前**把假设、指标、阈值全部写死并
存档，防止事后挑选对自己有利的分析方式。本项目的存于
`docs/PREREGISTRATION.md`。

| 门 | 检验什么 | 通过标准 |
|---|---|---|
| **G1** | **状态级**可解码性（能不能读出 V，水平量） | ΔR² > 0 且置信区间排除 0 |
| **G2** | **候选级**排序（能不能读出 A，差分量） | **Δconcordance ≥ 0.020** 且三个划分种子同号 |
| **G3** | 配对候选（把干扰因素匹配掉之后还有没有） | 准确率 ≥ 0.55 **且** 比控制高 ≥ 0.03 |

**kill gate（终止门禁）**：达不到标准就终止方向，**不允许事后加模型容量去"抢救"**。

> **为什么 G2 和 G1 要分开**：G1 是**池化**统计量，一个只懂"局面好坏"的读出器就能
> 满足它，**却对任何决策毫无帮助**。事后证明这正是本项目的关键。

**Phase S（资格认证）**：正式采集前先验证这个骨干能不能用（S1 去噪质量、S2 解码
连贯性、S3 任务结果混合度、S4 推演可行性）。

## 0.10 标签代号怎么读

格式：`字母` + `版本号`。

- **字母配对 = 同一个实验拆到两张卡上跑的两半文档**。例如 `a3` 和 `b3` 各 200 题、
  题号不重叠，**合并起来才是一次完整实验的 400 题**。不是两个实验。
- **数字 = 第几版**。`a/b` 是第一版（作废），`a2/b2` 是修 bug 后第二版，
  `a3/b3` 是 K=24 的正式版。

| 代号 | 骨干 | π_ref | 说明 |
|---|---|---|---|
| `a3` + `b3` | MDLM | 祖先采样 | **臂 1**（正式） |
| `c3` + `d3` | MDLM | 置信度 | **臂 2**（正式） |

## 0.11 其他缩写

| 缩写 | 全称 | 含义 |
|---|---|---|
| **OOF** | out-of-fold（折外） | 五折交叉验证时，每份数据都只由**没见过它**的模型预测。防止自评 |
| **D1 / D2** | frozen transfer / refit | **D1** = 旧数据上训好的读出器**原样搬到**新数据（零适配迁移）；**D2** = 在新数据上**重新拟合**。D2 为正而 D1 弱 = "信号存在但读出器换域就不灵" |
| **AURC** | Area Under Risk-Coverage curve | 风险-覆盖曲线下面积，衡量"按分数排序砍掉差的"整体收益 |
| **覆盖率 coverage** | — | 砍掉一批之后**保留**的比例。覆盖 50% = 砍掉一半 |
| **NELBO** | negative ELBO | 负证据下界，扩散模型的标准损失，**越低越好** |
| **安慰剂控制 placebo** | — | 把隐藏状态换成**等尺度随机噪声**再跑一遍。**它必须得 0**，否则说明流程本身有偏差 |
| **标签置换 label permutation** | — | 把标签**打乱**再跑一遍。**必须得 0**，否则说明有数据泄漏 |

## 0.12 统计方法（09-02 新增的那一批）

**为什么要用好几种**：每种方法的失效方式不同。它们一致时，结论就不是某一种方法的
产物。

| 方法 | 大白话 | 它防什么 |
|---|---|---|
| 朴素 t 检验 | 把 50 个种子当 50 次独立实验算平均 | **什么都不防，本项目列出它是为了展示它错在哪** |
| **Nadeau–Bengio 修正 t** | 同上，但把方差按 `(1/J + n_test/n_train)` 放大 | **重复划分同一批数据时训练集大量重叠、结果正相关；不修正就会凭空造出显著性** |
| 聚类 bootstrap | 按**文档**整块重抽 2000–4000 次，取分位数 | 同一文档内样本互相依赖，逐条抽会低估不确定性 |
| **BCa bootstrap** | 再纠正 bootstrap 分布的偏移(z0)和偏度(a) | bootstrap 分布不对称时分位数法会偏 |
| 刀切法（jackknife） | 每次去掉一篇文档重算 | 换一种重抽样机制交叉验证 |
| 符号检验 | 只数有多少个种子为正 | 几乎不假设分布 |
| Wilcoxon 符号秩 | 同上但用秩 | 比符号检验功效高 |
| **BH-FDR** | 跨探针的多重比较校正，给出校正后的 q 值 | 一次跑 8 个探针就有 8 次开火机会，不校正必然出假阳 |

> ### ⚠️ 「多跑种子」的陷阱（本项目实测）
> 划分种子跑得再多，**独立信息一点不增加**——切的是同一批文档、同一批标签。
> 朴素 t 会让区间按 `1/√J` 收缩，那个收缩是假的。
> **实测**：50 种子下朴素 t 给出 `p = 1×10⁻¹⁸`，Nadeau–Bengio 修正后同一份数据
> `p = 0.61`；区间宽度差 **4.67 倍**。
> 真正能增加信息量的是**更多数据**，不是更多种子。

**新增的第四个控制组**：`within_state_shuffle`（状态内打乱）——**只打乱"同一状态内
哪个候选拿到哪个隐藏向量"**，状态级内容、边缘分布全部保留。这是检验"隐藏态是否携带
**候选特异**信息"最干净的零假设，比跨行打乱更严格。

## C1 · G1「能不能读出局面好坏（V，水平量）」—— 唯一无争议的正结果

|---|---|---|---|
| 臂1 祖先采样 | **+0.183** | 75/78 | ✅ 通过 |

# 第 7 章 · AR→扩散改造（E1）

**在做什么**：前面都是"拿别人的模型做观察"。这一步是**自己造一个模型**——把一个
现成的自回归模型（AR，就是 GPT 那种从左往右写的）改造成扩散模型。这是业界主流
做法（DiffuLLaMA / DiffuGPT 路线）。

| 设置 | 值 |
|---|---|
| 底座 | SmolLM2-1.7B-Instruct |
| 语料 | 70% FineWeb-Edu + 30% smoltalk = 7.07 亿 token |
| 实际训练量 | **1.97 亿 token** |
| 单卡耗时 | 6.5 小时，17.1 GB 显存，8,481 token/秒 |

**改造的三个部件**：
1. **因果→双向退火**：原模型只能看左边，扩散要能看两边。突然切换会毁掉预训练
   表征，所以**渐进**放开。
2. **shift 对齐淡出**：AR 在位置 i 预测第 i+1 个词，扩散在位置 i 预测第 i 个。
   训练初期把输出左移一位复用预训练的头。
3. **新增 `[MASK]` 符号**，嵌入初始化为**现有嵌入的均值**（随机向量离流形太远）。

**手术正确性的决定性验证**：改造后第 0 步的损失必须与原模型完全一致——
原始 3.312130 vs 改造后 **3.312133**（差 2.6e-06）。

| 门 | 检验 | 结果 | 判定 |
|---|---|---|---|
| E1 | NELBO（扩散损失，越低越好） | **−33.4%** | ✅ |
| E2 | 生成质量 | 符号汤（乱码） | ❌ |
| E3 | 做数学题能力 | **0%** | ❌ |
| E4 | 有没有灾难性遗忘 | 各遮挡比例一致改善 29–35% | ✅ |

**评价**：改善是**均匀的**，这排除了"遗忘"假说，指向**训练量不够**——
1.97 亿 token 对 DiffuGPT 的 330 亿，是 **1/170**。

> ⚠️ **此项不能作为学术贡献声称**：任务书 "What NOT to claim" 里明确写着
> `AR→DLM conversion is a contribution`。

# 第 9 章 · G1 公平检验：一个被误设的测试（08-31）

## 缺陷 17 —— 本项目最严重的方法学错误

**问题出在哪**：`exp1b_within_state.py` 第 38–46 行，探针是在**原始目标 A** 上
拟合的，然后拿去在**同状态内残差**上打分。

**为什么这是错的**（大白话）：A 的变化绝大部分来自"局面之间的差别"，只有一小部分
来自"同一局面内候选之间的差别"。岭回归挑正则强度时是按**整体**误差挑的，所以它
完全可以**把全部力气花在区分局面上，对区分候选一点不做**。然后你拿它去考"区分
候选"，它当然不及格——**但这不能说明模型内部没有这个信息**。

**正确的做法**：把特征和目标**都按状态居中**（减掉各自状态内的均值），再拟合。
这样探针的**全部目标**就是"同一局面里哪个候选更好"这件事。

# 第 13.5 章 · 合并分析：把独立数据集**合起来**看（09-02）

## 为什么必须做这一步

第 13 章曾按"三个数据集里两个的区间含 0"判定状态级早停"未复现"。
**那是数票（vote counting），是一个已知的统计谬误**：在每个单独都功效不足的
独立研究上数有多少个"显著"，会系统性地把真实效应判成不存在。
正确做法是按精度加权**合并**。

**独立性说明**：以下三个数据集文档互不重叠（`vread` 用 GSM8K test 前 800 题；
taskC 为另一批 180 题；taskE 是 SVAMP，另一个数据集），
所以它们是**真正的独立重复**——与"划分种子"完全不同。

## 13.5-a 状态级早停：三个独立数据集，两个任务
