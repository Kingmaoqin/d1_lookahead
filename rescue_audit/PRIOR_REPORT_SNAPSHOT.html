一句话结论

冻结的掩码扩散语言模型，其隐藏表征线性携带的是"当前状态的价值 V"，而不是"某个候选动作的优势 A"。前者的增量 ΔR² = +0.183 / +0.320，在 layer×timestep 网格的 95–96% 格子里为正；后者在同状态内的排序能力停在随机水平（78 个格子里只有 40/78 与 30/78 为正）。08-30 把这条正结论推到了可用形式：冻结状态能预测这次生成最终答不答得对（AUC 0.890 对廉价特征 0.823，95% CI 排除 0），据此在半途砍掉一半在飞生成可省 30% 解码算力、留下那半的准确率从 56.7% 升到 86.9%——但题内 R² 为负、99.1% 的方差在题间，说明它读的是题目难度而非前瞻，因此仍是次要发现，不推翻 KILL 判定。四道预注册门禁中，G1 通过、G2 与 G3 失败 —— 两个参考策略、两个独立骨干（MDLM 与 SEDD）、三个推演视界上判定完全一致。

术语表

本文出现的每个非通用术语都在此处解释一次；正文中再次出现时会用括号简短提示。

DLM / 扩散语言模型
Diffusion Language Model。不像 GPT 那样从左到右逐词生成，而是从"全是掩码"的状态出发，反复迭代、每轮揭开若干个位置，直到填满整句。
掩码扩散 / masked diffusion
扩散语言模型的一种：加噪过程就是把词替换成特殊符号 [MASK]；去噪过程就是把 [MASK] 还原成真词。
absorbing（吸收态）
指 [MASK] 这个状态"只进不出"——一旦某位置在加噪中变成掩码就不再变化。是掩码扩散的标准数学设定。
unmasking order（揭示顺序）
解码时先揭开哪个位置、后揭开哪个位置。这是扩散语言模型独有的自由度，也是本研究的研究对象。
π_ref（参考策略）
一个固定下来的、可复现的解码器。所有"价值"都是相对于它定义的——换了 π_ref，同一个动作的优势值就不同。
ancestral sampling（祖先采样）
按模型自身的反向扩散过程解码：揭示顺序是均匀随机排列。它是掩码扩散模型"原本设计的"采样方式。
confidence 解码
每步挑模型最有把握（top-1 概率最高）的位置先揭开。是 MaskGIT / LLaDA 等工作的主流做法，也是 POKE / LookUM 实际操作的解码器。
rollout（推演）
从某个中间状态出发，让 π_ref 一路解码下去，看最终得到什么。本研究用它来"实测"未来价值，而不是估计。
Path-LL（路径对数似然）
Path Log-Likelihood。把一条解码轨迹上每次提交的词的对数概率加起来，衡量"这条路走得好不好"。POKE 论文提出的指标。
Q / V / A
强化学习记号。V(s)＝在状态 s 下按 π_ref 走的期望回报；Q(s,a)＝先做动作 a 再按 π_ref 走的期望回报；A = Q − V＝这个动作比"照常走"好多少，称为优势（advantage）。
CRN（共同随机数）
Common Random Numbers。让两条要对比的推演使用完全相同的随机数，这样它们的差值就只反映"动作不同"，而不掺杂随机波动。是方差缩减的标准手段。
Rao-Blackwell 化
一种方差缩减技巧：把"抽样得到的随机量"换成它的条件期望。期望不变（由全期望公式保证），方差严格更小。
probe（探针）
在冻结（不再训练）的模型隐藏状态上训练的一个小预测器。用它能不能预测某个量，来判断该量是否"被编码在表征里"。
linear probe（线性探针）
探针只允许是线性函数。若线性可读，才能说这个量被"线性表示"；若只有非线性能读出，则不能下这个结论。
ridge 回归 / 岭回归
带 L2 正则的线性回归。正则强度记作 α，α 越大模型越保守。
ΔR²（增量决定系数）
加入隐藏表征后，模型在留出集上的 R² 比只用"廉价控制特征"高出多少。本研究的主统计量。
within-state R²（同状态内 R²）
先把每个状态内部的均值从标签和预测里都减掉，再算 R²。它剥离了"这个状态好不好"，只剩"同一状态里哪个候选更好"。
concordance（一致率）
同一状态内任取两个候选，探针判断"谁的优势更大"判对的比例。随机猜是 0.5。这是调度器真正面对的决策。
noise ceiling（噪声天花板）
因为标签本身有测量噪声，任何预测器的 R² 都不可能超过某个上限。报告 R² 时必须同时报这个上限，否则数字没有意义。
SNR（信噪比）
标签里"真实信号方差"与"测量噪声方差"之比。低于 1 意味着噪声比信号大，此时的零结果没有信息量。
cluster bootstrap（聚类自助法）
重抽样时以"文档"为单位整块抽取，而不是逐条抽。因为同一文档里的样本互相依赖，逐条抽会低估不确定性。
kill gate（终止门禁）
开工前就写死的一组量化标准。达不到就终止方向，不允许事后加模型容量去"抢救"。
pre-registration（预注册）
在看到结果之前把假设、指标、阈值全部写死并存档，防止事后挑选有利的分析方式。
POKE / LookUM
两篇相关工作。它们在推理时花额外算力"向前模拟"来挑选揭示路径。本研究要问的是：它们花算力去搜的那个量，是不是本来就能从冻结表征里直接读出来。

科学命题与判定标准

要检验的那一句话

整个方向立在一句话上，它必须被实证支持，否则方向终止：

待检验命题

冻结的扩散语言模型表征，线性地暴露了"另一个候选解码动作的、由推演定义的未来路径价值"——而这个量无法从模型自身暴露的输出分布或廉价轨迹统计量中恢复。

这里每个限定词都是必要的。"线性地"排除了用大容量非线性头硬拟合；"由推演定义"意味着标签是实际跑出来的，不是从输出分布推导的；"无法从输出分布恢复"要求探针必须打败强控制组，而不只是打败置信度这一个标量。

为什么这个问题值得问

POKE 与 LookUM 这类工作在推理时花额外算力做"前瞻"（lookahead）：从当前状态向前模拟若干步，估计每个候选揭示动作的未来收益，再据此挑路径。如果这个被搜索的量本来就线性写在冻结模型的隐藏状态里，那么一次前向传播读出即可，前瞻搜索就是浪费。这是"表征发现优先"的研究：先问信息在不在，再谈能不能省算力。

关键发现二：朴素蒙特卡洛标签不可用

标签采集的试点（pilot，96 例，K=8）暴露出一个致命问题：推演噪声大于候选间信号。信噪比只有 0.1–0.6。若不修，任何探针都无法预测一个几乎全是噪声的标签，研究会产出一个假的否定结论。

解法是 Rao-Blackwell 化：把每次提交的打分从"实际抽到那个词的对数概率"换成"该分布下的条件期望"。由全期望公式（tower property），两者期望相同，但后者方差严格更小。

审计

计划

派出两个互不通气的独立审计代理：一个查实现正确性，一个查实验设计与统计。两者都因会话额度中断，未跑完，剩余项由本人接手完成。审计找到的问题足以推翻当时的全部结论。

致命缺陷 1 · 主标签在代数上被状态价值污染

Q 分支对 17 次提交取平均（1 次强制动作 + 16 次推演），V 分支只对 16 次。这个分母失配把 −V/17 直接注入了标签。

实测恒等式精确成立到浮点精度：max|误差| = 6.0e-08，相关系数 = 1.000000。后果是 corr(A_full, −V) = +0.589——所谓"优势"标签有一半以上按构造就是状态价值本身。

污染恒等式（已实测验证） Afull(错) = (ℓi + SQ)/17 − SV/16 ≡ [ (ℓi − V) + 16·Afuture ] / 17 其中 ℓi = log pθ(x̂i|st) 是被强制动作自身的对数概率，SQ、SV 是两支推演的路径打分和，V = SV/16 就是状态价值。由于隐藏态以 R²=0.93 预测 V，它当然能预测我们亲手注入标签的 V 分量——当时的头条结论因此是循环论证。
致命缺陷 2 · 两分支消耗的位置数不同

Q 分支填了 17 个被掩位置，V 分支填了 16 个。于是"提交一个容易的词"会显得有害——仅仅因为它把一个容易的提交从未来的池子里拿走了（称为耗尽效应，depletion）。

实测：corr(A_future, logp_action) = −0.440，且随扩散进度单调恶化到 −0.710。也就是说 A_future 很大程度上在测"这个词有多容易"，还带个负号，而不是规划价值。

修复：让两分支消耗相同数量的位置

修正后的估计量（当前定义） Q 分支： 强制提交 (i, x̂i)，再走 H 次 πref 提交 → 共 H+1 个位置，路径打分 = ℓi + SQ
V 分支： 直接走 H+1 次 πref 提交 → 共 H+1 个位置，路径打分 = SV

Afull = [ ℓi + SQ − SV ] / (H+1)
Afuture = [ SQ − (SV − vfirst) ] / H vfirst 是 V 分支在决策点自己那一次提交的打分，扣掉它之后两侧都是"决策之后的 H 次提交"，可比。为此给推演函数新增了 first_ll 返回值。Afull 对应 POKE 字面意义的 Path-LL 优势；Afuture 只保留动作的下游效应，是更难也更有意思的目标——因为动作自身的对数概率本身就是一个廉价控制特征。
修复验证

V_n = n_commit = 17（两分支位置数相等）；污染恒等式被打破（相关系数 1.000000 → 0.931）；耗尽效应从 −0.440 降到 −0.171。

诚实代价：修正后的标签更噪

这一点必须讲清楚，否则会被误读为"修复让结果变差了"。旧标签的"信号"里有相当一部分就是那个污染项——V 在状态间变化很大，看起来像信号。去掉之后剩下的是真实的、更小的优势信号。

是什么。一个冻结的扩散语言模型，其中间层隐藏状态线性携带"这次生成会不会成功"的信息，超出输出分布本身能提供的部分（ΔAUC +0.066，95% CI [+0.035, +0.099]，两道证伪控制归零）。这把项目唯一的正结论从代理统计量推进到了一个可直接使用的操作点。

不是什么。这不是前瞻（lookahead）。题内 R² 全负、99.1% 的方差在题间、隐藏块的优势不随去噪累积——三条证据一致指向：探针读到的是"这道题对我有多难"，一种自我认知/难度预测，而不是"这条解码路径走得好不好"。原任务书的命题是后者，本轮不构成对它的支持，更不构成对 08-24 至 08-28 那个 KILL 判定的推翻。

与任务书的关系。任务书把 VPathLLπ_ref 明确列为次要分析，所以做这件事在协议之内；同时它写明 kill 之后不得加容量来抢救——本轮全程线性探针、骨干冻结、无强化学习、无稀疏自编码器、无联合微调，符合该约束。但把次要发现改写成主命题是不诚实的，报告按次要发现记录。

算法与数学公式汇总

参考策略 π_ref

每步一次提交的解码循环 给定状态 st（= 词序列，被掩位置填 [MASK]）与掩码集合 M：

1. logits ← fθ(st) // 冻结骨干，一次前向
2. 对每个被掩位置取 top-k（k=50），得截断对数概率 lptop
3. 提议词 ← argmaxslot ( lptop/τ + Gumbel ) // τ=1.0；Gumbel-max ≡ 从 softmax(lp/τ) 抽样
4. 排序分数 sc:
    ancestral → sc = order_key（每条推演固定的随机排列键）
    confidence → sc = lptop[…,0] / order_temp + Gumbel
5. 提交 sc 最大的那个被掩位置；重复直到填满 用"每条推演固定的随机键 + 取最大"来实现均匀随机排列，而不是每步现抽——这样两条被耦合的推演会走同一个排列，耦合更紧。

共同随机数（CRN）

按 (种子, 流, 位置, 词ID) 索引的计数器型随机数 u = splitmix64( seed·C0 ⊕ stream ⊕ position·C1 ⊕ token_id·C2 ) / 253
Gumbel = −log(−log u) 关键设计：噪声按绝对位置与词 ID 索引，而不按步数或 top-k 内的名次。因为 Q 分支比 V 分支"快一步"，按步数索引会立刻失同步；按名次索引则在两分支 top-k 集合稍有差异时就完全打乱。每个位置每条推演只被揭示一次，故没有噪声被重复使用，π_ref 的边缘分布严格正确。
CRN 的决定性验证 · no-op 测试

强迫 Q 分支提交 V 分支本来就会提交的那个动作。若耦合完美，两条轨迹必须逐词完全相同、优势必须恰好为 0。实测：三种排序规则（ancestral / confidence 两档）全部 30/30 轨迹相同，误差恰为 0.000e+00。真实动作下 token 一致率 96–97%，逐种子 Path-LL 相关 0.925。

探针与推断

岭回归的 Gram 矩阵特征分解解法 XᵀX = VΛVᵀ ⟹ w(α) = V · diag( 1/(λ + α) ) · Vᵀ (Xᵀy) 比对 X 做 SVD 快约一个数量级（n≈9k、d≈1.6k 时），因为层扫描要拟合 13×3×2 个探针。在 GPU 上执行；与 sklearn 的 Ridge 对拍相对误差 1e-7（fp64）/ 1e-6（GPU fp32）。
噪声天花板与信噪比 观测方差 Var(Ā), 噪声方差 = En[ Vark(An,k) / K ]

天花板 = ( Var(Ā) − 噪声 ) / Var(Ā) // 任何预测器 R² 的上限
SNR = ( Var(Ā) − 噪声 ) / 噪声 // 低于 1 则零结果无信息 An,k 是第 n 个候选、第 k 条推演的配对差值。因为存了逐种子副本，这两个量可以直接算，不必假设。
refit-bootstrap（把拟合方差纳入区间） 对 b = 1…B：
   在各自不相交的 train / val / test 文档池内部分别有放回重抽
   在重抽的 train 上重新拟合两个模型，在重抽的 test 上评估，记录 Δ
取 Δ 的 2.5 / 97.5 分位数为 95% 区间 必须在划分内部重抽：先把全体文档有放回抽完再切分，会让重复文档同时落进 train 与 test（泄漏）。默认的固定模型 bootstrap 只重抽测试集，捕捉不到拟合方差，区间偏窄——而 G1 是唯一通过的门，区间偏窄会让"排除 0"过于容易。

在两个参考策略、两个独立骨干、三个推演视界、充足功效下，那句要检验的话没有得到支持。数据支持的是一句更窄且实质不同的陈述：

数据支持的陈述

在 MDLM-owt 上，冻结的掩码扩散表征线性地暴露了由推演定义的状态价值 Vπ_ref，远超强输出分布与轨迹控制组（ΔR² +0.183 / +0.320，状态级通道在 95–96% 的 layer×timestep 格子里为正）。

它没有在候选层面暴露动作优势：h_i——表征中唯一逐候选变化的部分——在同状态内的排序停在随机水平（concordance 正格数 MDLM 40/78 与 30/78、SEDD 38/78），在非循环匹配的配对候选上与暴露输出控制无显著差异。

为什么 G1 过了却不构成证据

ΔR² 在两臂都通过 G1，并且在 refit-bootstrap（含拟合方差）下存活。但 G1 是一个池化统计量：把所有状态混在一起算 R²，一个只懂"这个状态好不好"的读出就能满足它，却对任何具体决策毫无帮助。

h_global 在一个状态的所有候选上取值相同。它提升拟合优度，并通过遗漏变量校正让廉价特征排得略好——但它自己无法在候选之间做选择。这就是 G1 通过而 G2、G3 失败的机制，也正是预注册要求四门齐过、而不是只看一个头条数字的理由。

与 POKE / LookUM 的关系

POKE 与 LookUM 花测试时算力估计的是动作之间的比较。本研究的结论是：它们那个目标里能从冻结表征廉价读出的部分，恰恰是在被比较的动作之间不变的那部分。换句话说，可读出的是共同的基线，不是区分动作的差值——而后者才是搜索真正在找的东西。

SEDD 的例外，以及它为什么不改变结论

SEDD 上出现了唯一一处两骨干的实质差异：在 caliper 匹配下，cheap + h_i 拿到 0.634，相对最好控制 gap +0.105 且 CI 排除 0——这在 MDLM 两臂都没有出现。

这一条被追查到底而非挥手带过。先做安慰剂测试确认配对机制本身不偏（随机噪声隐藏块 gap −0.012，不打败控制），排除"程序产物"这个解释；再用非循环的 strict 匹配复验，效应失去显著性（gap +0.048，CI 含 0）；同时全量数据探针显示 h_i 对 concordance 的增量是 −0.0003。

结论：SEDD 确实比 MDLM 多携带一点候选级信号，但只在"暴露控制被匹配到无信息"的子总体上可见，且经不起非循环检验。而 G2 无论如何都不过——判定不依赖 G3 如何裁定。

三轮实验的教训

同一个陷阱在三个版本里重复出现：污染标签、K=8 修正、K=24 修正——每一轮的池化 ΔR² 都是正的且显著，每一轮拆开看都是状态级通道。区别只在于第一轮的信号有三分之二是我自己注入标签的污染。

所以对任何后续基座的建议是：先跑 Experiment 1b（把 h_i 与 h_global 分开），再看别的。"一个真实发现"与"一个状态价值读出就能满足的池化 ΔR²"之间的全部差别都住在这个分离里。
