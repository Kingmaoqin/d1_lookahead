# 对 Claude 并行实现与结论的交叉审计

日期：2026-09-01

## 总判断

Claude 的第二轮实现审计是有价值的：分块正则、gamma 网格、自助法重复文档
合并、SEDD 控制块缺失和非凸训练预算等问题都是真问题。它对 **Path-LL 冻结
迁移主端点未达到 +0.020** 的判断也成立。

但它在解释正结果时有一处系统性过度收缩：把“域内重新拟合 D2”与“旧域训练后
冻结迁移 D1”当成同一种复现。二者估计对象不同：

* D2 回答“新域里是否存在可学习信号”；
* D1 回答“旧域学到的同一读出器能否零适配迁移”。

因此，D2 为正而 D1 变弱时，正确结论是 **信号存在但读出具有域依赖**，不能写成
“信号已被证伪”。

## Claude 做对的部分

1. Path-LL 的预注册 D1 主端点只有约 +0.008 至 +0.010，低于 +0.020 实用阈值。
2. 修正分块惩罚后，Kronecker 交互在真实 Path-LL 数据上约为 0；同一实现能在
   植入双线性信号的合成数据上恢复约 +0.075，故该阴性结果可信。
3. 标签可靠性远高于 cheap 基线，阴性结果不能归因于测量天花板。
4. 旧聚类自助把同一文档的重复副本按原 state id 合并，区间偏宽；修正不反转
   Path-LL 主结论。
5. 只换成排序损失的 cheap 模型能解释旧 top-1 增益的一部分，说明目标函数匹配
   是必要控制。

## Claude 过度否定的部分

### 1. candidate-informative 亚组不是“被证伪”，而是迁移不稳定

同域重拟合 D2 的结果是：

* MDLM 发现集：`cheap+H - cheap` 约 +0.0256，修正 CI 排除 0；
* 独立 fresh D2：约 +0.0200，修正 CI 也排除 0。

冻结迁移 D1 则降到 L8 +0.0053 / L6 +0.0106。这个结果否定的是“旧读出器可
零适配迁移”，不是“新域内不存在该信号”。报告应把它列为 **两次 D2 为正、D1
迁移衰减的设计依赖线索**。

### 2. D2 的决策端点不能因 primary concordance 未过阈值而消失

fresh D2 中，隐藏探针相对 cheap 的 top-1、normalized regret、within-R² 三个
端点都为正并通过原判据。它们不能升级成预注册主结论，但应作为明确的正结果
报告，而不是只留下 “KILL”。

### 3. Task utility 是另一个问题，不受 Path-LL KILL 外推

旧 taskA/taskB 中 `corr(A_PathLL, A_task)` 只有约 +0.04，而锁定的候选隐藏排序
探针曾给出约 +0.054 的探索增益。因此 task utility 必须独立检验。新完成的
taskC 有 180 题 / 720 states / 4,320 候选，标签 within-state ceiling 约 0.943；
数据质量足以继续判断该方向。

## 目前可以自信保留的正结果

1. **状态级价值通道稳定存在**：fresh D1 的 Δwithin-R² 约 +0.0232，CI 明确
   排除 0。这是冻结表征的真实、可迁移正信号。
2. **域内 candidate-informative 读出为正**：两份 D2 数据均达到约 +0.020，
   但冻结跨域迁移变弱；应表述为域依赖，而非不存在。
3. **Task-C 关系型候选排序出现稳定探索信号**：三次文档划分中，rank-4
   双线性探针相对 cheap 的 Δconcordance 分别为 +0.0421、+0.0300、+0.0422，
   均值 **+0.0381**，而 shuffled-h_g / Gaussian-h_g 总体接近 0。
4. **目标函数匹配后仍有一条隐藏通道**：锁定第 12 层的成对 `cheap+hidden`
   相对成对 cheap 三划分均为正（+0.0459、+0.0037、+0.0195），均值
   **+0.0230**。这排除了“全部只是 MSE 基线过弱”的最强版本。

第 3 项正在用五折、每文档仅预测一次的原协议做最后区间估计；在该结果完成前，
它应标为强探索性正结果，而不是预注册确认性结果。

### 五折复核后的精确限定

五折 OOF 保留了正方向，但暴露出非凸训练种子敏感性：

* 使用独立初始化 100–104：bilinear−cheap = +0.0149，
  bilinear−no-interaction = +0.0072；
* 严格匹配广筛初始化 0–4：bilinear−cheap = +0.0270，
  bilinear−no-interaction = +0.0265。

两套区间都覆盖 0；而第二套中 shuffled/Gaussian 控制偶尔能追平真实 h_g。
因此可以自信说 **task utility 上存在值得扩样的候选排序信号**，但还不能把它
唯一归因于真实状态调制。这个不确定性已通过 `TASKD_PREREGISTRATION.md` 在新数据
出生前锁定：扩到总计 3,000 states，用冻结模型一次性区分真实 h_g、无交互、
shuffled 与 Gaussian 控制。

另一个必须保留的反证是：封存 Task-D 主模型时，在 Task-C seed-0 内部 test 上，
bilinear = 0.5526、no-interaction = 0.5239，但同训练预算的 neural cheap-only =
**0.5908**。所以广筛中相对 cheap ridge 的 +0.042 不能直接解释为隐藏态净增益；
它同时混入了基线模型类差异。Task-D primary 已把这个更强 cheap-only 锁为主基线。

## 口径修正

Task utility 的 A_task 大量并列。旧 `top1` 把第一个最大值指定为唯一 oracle，且
把所有候选等值的 state 也计入，会让常数预测出现虚高准确率。最终报告以
concordance（只比较真实标签不等的候选对）为主，并补充“并列友好、只在可决策
state 上计算”的 top-1；不再用旧 top-1 支撑正结论。

## 对另一边新增但尚未提交的 V-confidence 审计草案

2026-09-01 16:04 出现的 `scripts/audit_v_confidence.py` 说明另一边也开始主动
检查自己是否低估了 08-30 的状态价值读出。以下方向是好的，完成后应纳入报告：

* 单独报告 hidden-only，而不只报告可能被分块正则压回 cheap 的增量模型；
* 估算 within-prompt 观察方差扣除 rollout 标签噪声后的可解释信号方差；
* 为风险—覆盖面积和实际 operating point 给出文档聚类区间；
* 查看正方向是否贯穿多个预先记录的时间点。

但当前草案不能直接支撑其预想的强结论：

1. `bestname = max(..., key=r2_score(yte, ...))` 在**测试集**上从单层、3 层、
   5 层、9 层等模型中挑最好者，随后又在同一测试集 bootstrap。这个区间没有
   包含模型选择不确定性，必然乐观。模型必须只由 validation 选择，或在外层
   文档交叉拟合中完成整个选择流程。
2. 各 record point 使用相同文档、相同全局层/特征选择，不能称为“六个近独立
   复制”。可以称为时间方向一致性；若要联合显著性，必须按文档联合 bootstrap
   并处理多重比较。
3. 固定已训练模型的 test bootstrap 可刻画测试文档不确定性，但不包含重新训练
   与超参选择的方差。它可作条件区间，不能替代完整 nested/CV 复核。

因此这份草案体现了一个正确修正——状态价值正结果可能确实被低报——但需先修掉
测试集选优，才能把新增数字称为可信增强证据。

### 首轮落盘结果中可以立即保留的强正证据

`data/v_audit.json` 于 16:12 落盘后，可以把测试集选优与模型本身分开。脚本的
`hidden_1layer` 在进入 test 前已经只按 validation R² 从层和 `H_g/H_m` 中选定；
因此把它直接指定为报告模型（而不是再用 test 选 `bestname`）不会改变如下数字：

* cheap：R² = 0.3380，AUC = 0.8229；
* validation-selected single-layer hidden：R² = 0.4812，AUC = 0.8896；
* 差值：ΔR² = **+0.1433**，ΔAUC = **+0.0666**；
* 固定模型、文档聚类 test bootstrap：ΔR² 95% CI
  **[+0.0847,+0.2042]**，ΔAUC 95% CI **[+0.0378,+0.0981]**。

六个预记录时间点的 hidden-only − cheap ΔR² 分别为 +0.1171、+0.0769、
+0.1303、+0.1284、+0.0774、+0.1320，六个文档聚类区间均排除 0。它们共享
文档和全局 validation 选层，故是**时间一致性**而不是六次独立复制；但方向与
量级的一致性仍是强稳健性证据。

这显著加强了“状态级价值通道存在”的结论，且说明此前只强调约 +0.0232 的
增量 within-R² 确实低报了 hidden-alone 可读性。其边界也很清楚：目标是
`V_reward` 的状态级读出，不是候选内 action-value 排序，更不是 Task-D/E 的
任务效用。条件 bootstrap 没有包含重新训练方差，所以最终报告同时给出这个
限制，但不能因此把一个大幅、held-out、跨时间一致的正结果抹掉。

直接针对 prompt 内中心化目标的补充拟合也给出了重要边界。观察到的 prompt 内
方差为 0.01478，K=8 rollout 均值引入的标签噪声方差仅 0.00192，折算噪声校正
天花板约 **0.870**；因此“没有题内读出”不能归咎于标签太噪。把 cheap、hidden
和目标都按 prompt 中心化后，cheap-within R² = +0.0013；在 L0/L3/.../L24
加入 masked-mean hidden 后仍全部为 +0.0013（增量精确 0，分块拟合选择了
hidden 空转）。这支持的机制表述是：

* **强正结果**：冻结 hidden 表征包含远超输出侧 cheap 特征的题目难度/模型
  自我评估信号；
* **强边界**：在这个线性、均值池化读出族里，没有发现同一题生成过程中的
  `V_reward` 波动通道。

实用端点同样不应被“不是前瞻”一句抹掉。validation-selected 单层 hidden 相对
cheap 的正确率增益，在 coverage 70%/50%/30% 分别为 +0.0236
[+0.0025,+0.0423]、+0.0612 [+0.0247,+0.0926]、+0.0794
[+0.0299,+0.1368]；风险—覆盖面积增益 +0.0464 [+0.0170,+0.0812]。
这些是 held-out 文档上的实际筛选价值。正确写法是“有用的难度/自知信号，
不是轨迹内 lookahead”，而不是把前半句删掉只留下限制。

## Path-LL 候选差分的直接 centered-target 重测

另一边随后正确指出：旧 `exp1b_within_state.py` 在原始 pooled 目标上拟合，再
事后计算 within-state R²；这不是直接优化调度器面对的状态内差分。新草案
`scripts/audit_A_fairtest.py` 把 cheap、`h_i` 和目标都在每个 state 内中心化，
再用相同文档 split、validation 选层和嵌套分块 ridge 拟合。

第一版误写目标键 `A_full`（真实键为 `A_pertok`），所以主目标被异常捕获后跳过；
但 seed-0 的 `A_future` 已产生有效点估计与 R² 区间：

| 臂 | within ceiling | Δwithin-R² | 文档 bootstrap 95% CI | Δconc | Gaussian placebo ΔR² |
|---|---:|---:|---:|---:|---:|
| ancestral a3/b3 | 0.791 | **+0.0124** | **[+0.0071,+0.0177]** | +0.0089 | 0.0000 |
| confidence c3/d3 | 0.735 | **+0.0192** | **[+0.0113,+0.0268]** | +0.0100 | +0.0028 |

这组结果推翻的是“候选差分精确为零”的过强措辞：直接为 centered 目标训练后，
两臂都有小而可靠的 `h_i` 增量。它目前没有推翻预注册实用门槛：Δconcordance
仍只有约 +0.009～+0.010，低于 +0.020。

草案的 concordance bootstrap 再次把重抽到的同一文档副本保留原 state id，
会产生此前已确认的 m² 分组缺陷；因此上述 Δconc **点估计可用，区间暂不用**。
Δwithin-R² bootstrap 只是把重复文档作为行权重，未调用 state 分组，故不受这个
特定缺陷影响。修正后的 `A_pertok` × 三 split 重跑正在进行，最终只能作为
看过旧结果后的公平性/稳健性重测，不回写成预注册确认。
